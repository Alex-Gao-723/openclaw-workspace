01 / 大模型技术栈

从预训练到推理优化

理解 LLM 的三层架构：基础能力层、推理优化层、应用接口层

⚡
基础层
BASE LAYER — 模型能力的根基

Transformer 架构

Self-Attention 的 Q/K/V 机制是理解一切 LLM 的基础。RoPE 位置编码优于传统正弦编码，更适合长文本外推。

预训练范式

自回归（GPT）为主流，Next Token Prediction 是核心。理解其局限性：推理能力弱于显式 CoT。

微调技术

SFT 对齐格式，RLHF/DPO 对齐偏好。DPO 比 PPO 更稳定，KTO 无需成对数据。

参数高效微调

LoRA 是工业界标配；QLoRA 用 NF4 量化可在消费级 GPU 微调 65B 模型。

上下文学习 ICL

ICL 本质是隐式梯度下降；CoT 显著提升推理能力但增加 token 消耗。

🚀
推理优化层
OPTIMIZE LAYER — 部署性能的关键

KV Cache

缓存历史 token 的 K/V 向量，避免重复计算。显存占用随序列长度线性增长，是长文本瓶颈。

模型量化

INT8/INT4/FP8 降低权重精度。GPTQ/AWQ 静态量化，SmoothQuant 动态量化。部署必备。

投机解码

小模型草稿 + 大模型验证，并行生成。长文本生成加速 2-3 倍，代码生成效果尤佳。

连续批处理

vLLM/SGLang 的 PageAttention 动态调度。相比静态批处理吞吐提升 10x+，服务化核心。

模型蒸馏

大模型教小模型，保留能力降低成本。如 Llama-3.2 1B/3B distilled from 70B/405B。

🔌
应用接口层
INTERFACE LAYER — 连接应用与模型

Function Calling

模型输出结构化工具调用参数。本质是结构化 JSON 生成，Schema 约束用 constrained decoding。

Structured Output

强制输出符合 JSON Schema。OpenAI/Claude 都支持，比 Function Calling 更通用。

System Prompt 工程

分层设计：Global System → Task-specific → Few-shot Examples。定义模型角色和行为边界。

多模态能力

文本+图像+音频统一处理。CLIP/LLaVA 架构理解；趋势是原生多模态（GPT-4o、Gemini）。

02 / RAG 检索增强生成

从简单检索到高级架构

查询理解

Query Rewriting、HyDE、Query Expansion。用户原始 Query 往往不适合直接检索；HyDE 用 LLM 生成假设文档再 Embedding 检索，解决词汇鸿沟。

混合检索

Dense Retrieval（Embedding）+ Sparse Retrieval（BM25）。Embedding 擅长语义，BM25 擅长精确匹配；RRF 融合通常最优。

向量数据库选型

Milvus、Qdrant、Weaviate、PGVector。关注：过滤能力、混合搜索、多租户、云原生。本质是索引和查询优化问题。

Embedding 模型

OpenAI text-embedding-3、BGE、GTE、E5。领域微调 Embedding 比通用模型检索准确率高 30%+。

重排序 Reranker

两阶段架构：双塔快速召回 + 交叉编码器精排。重排序是性价比最高的优化点，如 bge-reranker。

上下文组装

盲目塞满上下文会稀释注意力。关键信息放开头和结尾——LLM 存在「中间遗忘」效应。需截断、摘要、过滤。

高级 RAG 架构

Self-RAG

解决：生成内容无依据、幻觉

模型自反思：检索 → 生成 → 判断是否需要再检索 → 迭代。让模型自己决定「我是否知道」以及「我还需要查什么」。

Corrective RAG

解决：检索结果质量差

评估检索文档相关性，低质量时切换网络搜索或改写查询。动态修正检索路径，避免垃圾进垃圾出。

GraphRAG

解决：跨文档全局推理弱

构建实体关系图谱，利用社区发现提取全局主题。适合企业知识库，实现「连接碎片化知识」的全局理解。

RAPTOR

解决：长文档层级理解

自下而上聚类摘要，构建树状索引。适合书籍、论文等长文本，实现从细节到概览的多层级检索。

Adaptive RAG

解决：不同问题需要不同复杂度

先分类问题复杂度：简单问题直接答，复杂问题多步检索。避免「杀鸡用牛刀」的资源浪费。

⚠️ 企业 RAG 落地五大挑战

1. 数据预处理

PDF/Word/Excel 解析质量决定上限。表格、图片、多列布局是难点，需专门的文档解析管道。

2. 增量更新

向量库如何高效处理文档增删改？不能全量重建。需要增量索引更新策略和版本控制。

3. 权限隔离

不同用户看到不同内容。向量库需支持 metadata 过滤 + ACL，与企业 IAM 系统集成。

4. 评估体系

三维指标：Retrieval Accuracy + Answer Faithfulness + Answer Relevance。不能只看生成流畅度。

5. 幻觉控制

即使检索了也可能编造。需要 Citation 机制（让模型引用来源）+ 事实核查层。

03 / Agent 框架

从 ReAct 到 Multi-Agent 协作

Agent 是 LLM 的「手脚和记忆」，核心在于规划、工具使用与反思的闭环

核心范式对比

范式 代表 工作机制 适用场景
ReAct 最经典 Thought → Action → Observation 循环 通用工具使用；简单任务
Plan-and-Solve Plan-and-Execute 先制定计划，再逐步执行 复杂多步任务；需要全局规划
Reflection Reflexion 执行 → 评估 → 反思 → 重试 代码生成、写作等需要迭代的任务
Multi-Agent AutoGen、CrewAI 多个 Agent 分工协作 复杂系统：研究员+写手+审核员
DAG/Workflow LangGraph 预定义执行图，节点是 Agent/工具 企业流程自动化；确定性高

Agent 六大组件

🔧

工具 Tools

扩展 LLM 能力到外部世界。设计原则：原子性、幂等性、错误可恢复。Tool Schema 要清晰明确。

🧠

记忆 Memory

短期记忆（Buffer/Window）+ 长期记忆（Vector Store）。Entity Memory 提取关键实体实现结构化记忆。

📋

规划 Planning

将复杂目标分解为可执行步骤。LLM-based planning 不稳定，需结合规则引擎提升可靠性。

👁️

观察 Observation

感知环境反馈。不仅是文本，也可以是系统状态、错误码、用户反馈。观察质量决定决策质量。

⚡

行动 Action

区分信息收集类（搜索、读取）vs 副作用类（发送邮件、修改数据）。副作用操作需审计和确认。

🔄

反思 Reflection

执行后评估结果，识别错误并调整策略。Reflexion 模式通过「自我批评」实现持续改进。

⚠️ Agent 工程六大陷阱

🌀 循环陷阱

Agent 在 Tool 间无限循环。解法：设置最大步数；引入「放弃」机制；规划阶段设定终止条件。

🎯 工具选择失误

选错工具或参数错误。解法：Function Calling Schema 详尽；增加 Tool 描述；提供 Shot 示例。

💥 上下文爆炸

多轮后上下文超限。解法：关键信息提取到工作记忆；定期摘要历史；多层级记忆架构。

🎭 幻觉计划

制定的计划不可执行。解法：计划后验证可行性；结合确定性规则引擎；人介入关键决策点。

⏱️ 延迟问题

多步 Agent 响应慢。解法：流式输出每步状态；并行执行独立分支；预加载常用结果。

🛡️ 安全边界

Agent 执行危险操作。解法：权限分级；副作用工具需确认；沙箱执行；完整审计日志。

RAG + Agent 的统一架构

数据分析

复杂问题

🔗 协同关系

RAG 作为 Agent 的工具

Agent 把 RAG 当作「知识检索工具」，在需要事实时调用。工具调用返回的检索结果作为 Observation 输入。

Agent 增强 RAG

Agent 可以自主决定检索策略：改写 Query、换数据库、多轮检索。自适应检索策略提升召回质量。

记忆层统一

Agent 的长期记忆和 RAG 的向量库共享基础设施。用户偏好、历史对话、企业知识统一检索。

05 / 评估与监控

决定成败的最后一公里

常被忽视但决定系统上限：建立完整的评估-监控-优化闭环

DIMENSION 01

检索质量

  • Hit Rate（命中率）
  • MRR（平均倒数排名）
  • NDCG（归一化折损累积增益）
DIMENSION 02

生成质量

  • 幻觉率（Hallucination Rate）
  • Faithfulness（忠实度）
  • Relevance（相关性）
DIMENSION 03

Agent 效果

  • 任务完成率
  • 步数效率
  • 工具使用准确率
DIMENSION 04

系统性能

  • P95 延迟
  • 吞吐量 QPS
  • 错误率
DIMENSION 05

成本控制

  • Token 消耗
  • API 调用次数
  • 缓存命中率
